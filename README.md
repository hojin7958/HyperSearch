# Hyperfinder 0.3.0

Windows 개인용 Rust 파일 검색기입니다. 파일·폴더 이름과 전체 경로를 검색합니다. 다크테마, 처음 실행 시 기본 9pt 글꼴, 파란 돋보기 아이콘을 사용합니다. 기존에 저장한 글꼴 크기는 유지합니다. 검색창·검색 옵션·새로고침·전체 재색인·설정은 상단 한 줄에 배치합니다. 화면은 Win32 기본 컨트롤로 구성하며, 결과가 많아도 보이는 행만 표시하는 가상 목록을 사용합니다.

## 실행과 사용법

배포할 때는 `Hyperfinder.exe` 파일 하나만 공유하고 실행하면 됩니다. 고속 인덱서도 이 실행파일 안에 포함되어 있습니다. `qf-bench.exe`는 개발용 성능 측정 도구이며 일반 실행에는 필요하지 않습니다.

기본 검색 범위는 로컬 고정 드라이브입니다. 설정에서 원하는 폴더로 바꿀 수 있습니다.

## 업데이트

[GitHub Releases](https://github.com/hojin7958/HyperSearch/releases/latest)에서 `Hyperfinder.exe`를 내려받아 실행하세요. 0.2.0을 사용 중이면 트레이 메뉴에서 완전히 종료한 뒤 새 실행파일로 한 번 교체해야 합니다. 설정과 인덱스는 기존 `%LOCALAPPDATA%\QuickFind` 폴더를 그대로 사용합니다.

0.3.0부터 **설정 → 업데이트 확인**으로 최신 정식 버전을 확인하고 설치할 수 있습니다. 시작할 때 백그라운드에서도 확인하며, 설정의 **시작할 때 새 버전 확인**을 끄고 저장하면 수동 확인만 합니다. 자동 확인은 파일을 설치하거나 앱을 종료하지 않습니다.

새 버전을 설치하면 GitHub의 실행파일 크기와 SHA-256을 확인한 뒤 앱을 종료하고 실행파일을 교체하여 다시 실행합니다. 진행 중인 파일 작업이나 인덱싱이 있으면 다운로드 후 설치를 기다립니다. 설치 위치에 쓰기 권한이 필요하며, 교체 실패 시 기존 실행파일을 유지하고 재실행 실패 시 이전 실행파일을 복원합니다. 사용자 설정·검색 인덱스·원본 파일은 업데이트 대상으로 다루지 않습니다. 인터넷 연결 오류와 GitHub 요청 제한은 설정 화면에 표시하며 다시 확인할 수 있습니다.

### 새 버전 배포

`Cargo.toml`의 버전을 올리고 변경사항과 `Cargo.lock`을 커밋한 후 실행합니다. Windows 실행파일의 버전 정보는 Cargo 버전으로 자동 생성됩니다.

```powershell
# 검사·빌드·패키징만 수행: _workspace/releases/v버전/
.\scripts\release.ps1

# 같은 검사 후 소스·태그·릴리스 게시 (GitHub CLI 로그인 필요)
.\scripts\release.ps1 -Publish -NotesFile .\release-notes.md
```

공개 릴리스에는 `Hyperfinder.exe`, 버전별 ZIP, `SHA256SUMS.txt`가 포함됩니다. 앱은 이 저장소의 최신 정식 릴리스만 확인하며, 초안·시험 버전·같거나 낮은 버전은 설치하지 않습니다. `_workspace`의 개인 설정·인덱스·백업은 공개 소스에서 제외합니다.

## 주요 기능

- `Ctrl + Alt + 1`: 검색창 호출. 검색창이 활성화되어 있으면 숨김. 설정에서 단축키를 변경할 수 있습니다.
- 검색창을 클릭하거나 키보드로 포커스를 옮기면 검색어 전체를 선택합니다. 바로 입력하면 새 검색어로 바뀝니다.
- 결과 한 번 클릭: 파일명을 포함한 전체 경로 복사. 파일 복사·잘라내기가 클립보드에 있으면 붙여넣을 수 있도록 그대로 유지합니다.
- 선택한 파일·폴더를 마우스로 끌어 탐색기나 파일을 받는 프로그램에 놓을 수 있습니다. 여러 항목 선택도 지원하며, `Ctrl`을 누르면 복사, `Shift`를 누르면 이동합니다. 기본 동작은 대상 프로그램이 결정하고 `Esc`로 취소할 수 있습니다.
- 열 제목 클릭: 이름·폴더 경로·크기·생성일·수정일 정렬 및 방향 전환. 새 설정의 기본값은 **수정일 역순**입니다.
- `Esc`, 창 닫기: 종료하지 않고 트레이로 숨깁니다. 실행파일을 다시 실행하면 기존 창을 다시 엽니다.
- 트레이 오른쪽 클릭: 열기 / 종료. 완전히 종료하려면 트레이의 종료를 선택합니다.
- `Ctrl + F`, `Ctrl + L`: 검색창 선택. `Ctrl + A`: 검색어 전체 선택.
- 검색창에서 아래 화살표: 결과로 이동. 결과에서 `Ctrl + C`: 파일 복사, `Ctrl + X`: 파일 잘라내기, `Ctrl + V`: 파일 붙여넣기. 탐색기와 파일 클립보드를 주고받으며, 폴더를 선택하면 그 폴더 안에, 파일을 선택하면 그 파일의 상위 폴더에 붙여넣습니다. 이름 충돌은 Windows에서 확인합니다.
- 결과에서 `Ctrl + Shift + C`: 경로 문자열만 복사. 검색어·이름 편집 중에는 Windows의 일반 텍스트 복사·잘라내기·붙여넣기가 동작합니다.
- 선택한 결과를 마우스로 끌어 파일 탐색기 등 다른 프로그램에 드롭할 수 있습니다. 길게 누르는 대기시간 없이 Windows의 기본 이동 감지로 시작하며, 준비할 때 이미 검색된 파일 정보를 사용합니다. `Ctrl` / `Shift`의 복사·이동 동작은 대상 프로그램의 Windows 기본 규칙을 따릅니다.
- 이름 열 더블클릭 또는 `Enter`: 파일·폴더 열기. 폴더 경로 열 더블클릭: 해당 열에 표시된 폴더를 탐색기로 열기. 크기·날짜 열 더블클릭은 파일을 열지 않습니다.
- 결과 오른쪽 클릭: **경로 열기 (파일 탐색기)**를 누르면 파일은 상위 폴더에서 선택하고, 폴더는 그 폴더를 엽니다. 실제 탐색기 클래식 파일 메뉴의 연결 프로그램·복사·이름 변경·삭제·속성과 전체 경로 복사도 제공합니다.
- `F2`: 선택한 결과 이름 변경. 같은 이름의 다른 파일을 덮어쓰지 않습니다.
- 결과를 선택하고 `Delete`: 전체 경로를 표시하는 확인창에서 **예**를 선택하면 삭제합니다. 기본 선택은 **아니요**입니다. 가능한 경우 휴지통으로 보내며, 영구 삭제가 필요하면 Windows에서 추가 확인합니다. 폴더는 내부 항목도 함께 삭제됩니다. 검색어·이름 편집 중에는 글자만 지우고, `Shift + Delete` 영구 삭제 단축키는 제공하지 않습니다.
- 설정: 단축키·검색 폴더·제외 폴더·글자 크기·시작 시 고속 동기화를 변경합니다.
- 검색어의 일치 부분을 노란 배경으로 강조합니다. `*보고서*`는 `보고서` 부분을 강조하며, 전체 경로 검색과 정규식도 지원합니다. 홀수·짝수 행 음영도 더 뚜렷하게 구분합니다.
- `Ctrl + 클릭`: 개별 항목 선택·해제. `Shift + 클릭` / `Shift + ↑↓`: 범위 선택. 목록의 `Ctrl + A`: 전체 선택. 복사·잘라내기·삭제·경로 복사는 선택 항목 전체에 적용합니다. 파일 작업은 한 번에 4,096개, 경로 합계 2MiB까지이며 초과 시 일부만 처리하지 않고 안내합니다. 부모 폴더와 그 안의 파일을 함께 선택하면 부모 폴더 작업에 포함합니다. 붙여넣기 대상과 이름 변경 대상은 하나만 선택합니다.
- 설정의 단축키 칸을 클릭하고 실제 키 조합을 누른 뒤 저장하세요. 입력 중에는 기존 전역 단축키를 잠시 해제하고 칸을 떠나거나 설정을 닫으면 복원합니다. 윗줄 `1`과 숫자패드 `Num1`을 구분합니다.
- 검색 폴더의 **추가…**는 Windows 폴더 선택 창을 엽니다. 여러 폴더를 추가하거나 목록에서 선택 후 **삭제**할 수 있습니다. 이 삭제는 검색 범위에서만 제외하며 실제 폴더는 지우지 않습니다. 글꼴은 **8~20pt**로 설정할 수 있습니다.
- 설정의 **제외 폴더 (하위 항목 포함)**에서 **추가…**로 폴더를 선택하고 **저장**하면 해당 폴더와 모든 하위 파일·폴더가 검색 목록과 자동 갱신에서 제외됩니다. **해제**는 선택한 폴더를 제외 목록에서만 제거합니다. 제외를 해제하고 저장하면 고속 동기화로 다시 포함하므로 관리자 권한 확인이 나타날 수 있습니다. 실제 파일·폴더는 삭제하지 않으며 제외 설정은 다음 실행에도 유지됩니다. `제외` 폴더를 설정해도 `제외2`처럼 이름만 비슷한 다른 폴더에는 적용되지 않습니다.
- 새로고침 / `F5`: 고속 변경분 동기화. 전체 재색인 / `Shift + F5`: NTFS 전체 목록을 다시 수집합니다.

검색어, 검색 옵션, 정렬 기준과 방향, 열 너비, 창 위치·크기·최대화 상태를 기억합니다. 변경한 설정은 잠시 후 저장하며 창을 숨길 때도 저장합니다.

| 검색어 | 동작 |
|---|---|
| `보고서` | 이름에 보고서 포함 |
| `*보고서*` | 보고서를 포함하는 와일드카드 |
| `*.pdf` | PDF 파일명 |
| `보고서_??.xlsx` | 물음표 하나당 한 글자 |
| `*{{변수}}*` | 중괄호를 포함한 실제 문자열 검색 |
| `^보고서_\d{4}\.pdf$` | 정규식 체크 후 사용 |

기본 검색은 대소문자를 구분하지 않습니다. 전체 경로·대소문자·정규식 옵션과 파일/폴더 필터를 선택할 수 있습니다. 잘못된 정규식은 상태 영역에 표시합니다. 파일 아이콘은 Windows에 등록된 확장자 연결을 사용하며, 폴더 전체 용량은 합산하지 않고 `—`로 표시합니다.

## 인덱싱과 변경 반영

일반 실행의 인덱싱과 **새로고침 / F5**는 같은 실행파일의 인덱싱 모드를 관리자 권한으로 실행하여 NTFS 정보를 읽습니다. 기존 스냅샷과 USN 변경저널이 유효하면 변경분을 이어 읽고, 처음 실행하거나 저널이 유실·변경되면 MFT에서 전체를 다시 수집합니다. 수정일 필터를 쓰지 않으므로 삭제·이름 변경·예전 날짜가 유지된 파일의 유입도 동기화합니다. 검색창 자체는 일반 권한으로 유지됩니다. 이 모드는 로컬 NTFS 드라이브를 대상으로 하며 네트워크·비 NTFS 경로는 고속 인덱싱 대상이 아닙니다.

**전체 재색인 / Shift + F5**는 기존 고속 스냅샷을 재사용하지 않고 MFT부터 다시 수집하는 복구용 기능입니다. 고속 보조 프로그램은 원본 볼륨을 읽기 전용으로 열며 권한 설정이나 USN 저널을 변경하지 않습니다. 관리자 권한 확인을 취소하면 기존 저장 목록을 계속 사용할 수 있습니다. 새 설정은 시작 시 변경분 동기화가 기본이며, 저장 목록을 먼저 표시한 뒤 동기화합니다. 설정에서 시작 시 자동 동기화만 끌 수 있고 수동 새로고침은 계속 고속 방식을 사용합니다.

시작 시에는 저장 목록의 첫 검색 결과를 표시한 뒤 약 1초 후 자동 동기화를 시작합니다. 자동 시작 작업은 낮은 CPU·디스크·메모리 우선순위로 실행하며, 검색이나 파일 작업의 결과 교체가 진행 중이면 잠시 기다립니다. 동기화가 끝나도 새 검색·정렬 결과가 준비될 때까지 기존 목록 전체를 유지합니다. 보조 작업이 이미 저장한 인덱스를 GUI에서 다시 저장하지 않습니다. 파일 형식 아이콘도 별도 스레드에서 조회하므로 Windows Shell이나 Office 아이콘 처리 때문에 초기 화면 그리기가 기다리지 않습니다. 아이콘이 준비되는 동안에는 기본 아이콘을 표시합니다. 저장한 검색어와 자동 동기화 설정은 유지하며 수동 새로고침은 바로 시작합니다.

앱 실행 중에는 Windows 파일 변경 알림을 경로별로 합쳐 변경된 항목과 필요한 하위 폴더만 갱신합니다. 검색창이 활성화되어 있으면 약 0.9초 단위로 반영하고, 다른 창을 사용하거나 검색창을 숨긴 동안에는 최대 약 15초 동안 모아서 반영합니다. 실제 메타데이터가 같은 중복 알림은 기존 검색·정렬 캐시를 재사용합니다. 대기 변경이 4,096개 경로 또는 경로 데이터 약 2 MB를 넘으면 경로를 버리지 않고 변경된 상위 폴더들로 압축합니다. 폴더 복구는 활성 창에서 약 2초, 그 외에는 약 5초까지 모으며 새 알림이 계속 들어와도 처리 기한을 연장하지 않습니다. 변경 폴더는 최대 256개로 합치고, 필요하면 해당 검색 루트까지 범위를 넓히되 검색 범위 밖으로 확대하지 않습니다. 한 폴더에서 발생한 대량 변경 때문에 다른 드라이브까지 다시 탐색하지 않습니다.

변경 알림 자체가 누락되어 범위를 알 수 없으면 관리자 권한 확인 없이 백그라운드에서 전체 검색 범위를 복구합니다. 변경 감시의 연결·재연결·해제는 전용 스레드에서 수행하며, 일반적인 대량 알림에는 감시를 재연결하지 않습니다. 복구 중 새 알림은 별도 배치에 보관해 후속 갱신으로 처리합니다. 검색 루트 전체를 탐색한 뒤에는 최소 30초 간격을 두어 전체 복구가 연달아 실행되지 않게 합니다. 이 대기는 일반적인 부분 갱신을 늦추지 않습니다. 자동 복구 중에도 마지막으로 반영한 목록은 캐시에 저장하여 변경이 계속될 때 저장까지 미뤄지지 않게 합니다. 복구 실패 시 기존 목록을 유지하고 30초 뒤 다시 시도합니다.

접근 제한이나 공유 잠금이 있는 항목이 섞여 있어도 갱신 가능한 항목은 계속 반영하고, 확인할 수 없는 기존 항목은 보존합니다. 정션·심볼릭 링크는 항목 자체를 표시하되 연결된 디렉터리 안으로 재귀 탐색하지 않습니다.

자동 갱신 중에도 기존 인덱스와 결과 목록 전체를 유지하므로 검색어 입력, 검색, 스크롤과 복사를 계속 사용할 수 있습니다. 새 인덱스의 검색·정렬까지 별도 작업에서 마친 뒤 일치하는 인덱스와 결과 행을 함께 교체합니다. 준비 중 검색어를 바꾸면 최신 검색어로 다시 준비하며, 스크롤 위치나 선택이 바뀌어도 가능한 범위에서 유지합니다. 복구·정렬 준비 작업은 검색 작업과 분리된 최대 2개 스레드에서 낮은 CPU·디스크·메모리 우선순위로 실행합니다. 폴더 탐색은 짧은 작업 단위 사이에 쉬고 취소 여부를 확인합니다. 이전 인덱스의 메모리 해제도 화면 스레드 밖에서 수행합니다. 우클릭 메뉴, 이름 변경이나 파일 드래그 중에는 결과 교체를 미룹니다. 대량 변경 복구에서 읽지 못한 폴더는 이전 기록을 보존하며 제외 폴더 설정도 계속 적용합니다.

저장 목록을 불러온 직후에는 앱이 종료되어 있던 동안의 변경이 아직 반영되지 않았을 수 있습니다. 상태 영역의 동기화 안내를 확인하세요.

고속 동기화 후 검색 캐시를 중복 저장하던 작업을 제거했습니다. 동일 NTFS 상태 파일을 이용한 3회 측정에서 상태 파일 로드는 중앙값211→180ms, 저장은400→156ms로 줄었습니다. 새로고침 전체 시간의 비교는 아니며, [단계 측정 기록](qa/refresh-io.json)에 범위와 원본 수치가 있습니다.

C:처럼 드라이브 전체를 검색할 때 파일마다 만들던 임시 경로와 파일명 복사를 줄였습니다. 동일 자료의 목록 재구성 단계는 중앙값2.92→1.74초로 줄었고 생성 항목 수와 인덱스 할당량은 같았습니다.

## 메모리와 측정 기록

이름 문자열을 공유하고 파일 기록을 압축한 메모리 인덱스를 사용합니다. 검색 결과 ID는 4바이트이며 정렬 캐시는 한 열만 유지합니다. 저장 형식은 버전이 있는 바이너리 캐시이며, 이전 V1 캐시는 불러올 때 새 메모리 구조로 변환하고 이후 저장 시 V2로 기록합니다.

2026-10-15 이 PC에서 저장된 C: 인덱스 2,815,958개를 이용한 엔진 측정값입니다. [benchmark-v2-final.json](qa/benchmark-v2-final.json)에 원본 기록이 있습니다.

| 항목 | 측정값 |
|---|---:|
| 엔진 프로세스 작업 집합 | 147.49 MiB |
| 인덱스 할당량 | 약 126.11 MiB |
| 저장 인덱스 불러오기 | 약 202 ms |
| `보고서` 검색 중앙값 | 약 28 ms |
| `*.pdf` 검색 중앙값 | 약 43 ms |
| 반복 전체 정렬 | 약 3.0~3.8 ms |

이 값은 검색 엔진 벤치마크입니다. GUI 프로세스의 최종 메모리 사용량이나 키 입력부터 화면 표시까지의 지연을 의미하지 않습니다. 최초 정렬 캐시 준비는 반복 정렬보다 오래 걸립니다.

NTFS 고속 인덱싱은 이 PC의 C:에서 **2,815,906개 항목을 13.925초**에 수집했습니다. 일반 스캔에만 있던 181개 경로를 확인했으며, 179개는 삭제되었고 2개는 스캔 시작 후 다시 생성된 임시 데이터베이스 파일이었습니다. 이후 USN 변경 3,208건은 전체 재수집 없이 7.771초에 반영했습니다. 생성·수정·이름 변경·삭제와 상위 폴더 날짜를 포함한 테스트 항목 9개가 모두 일치했습니다. [ntfs-validation.json](qa/ntfs-validation.json)에 비교 수치를 기록했습니다.

약 281만 항목을 표시한 최종 GUI의 동기화 후 작업 집합은 **약170 MiB**, private commit은 약140 MiB였습니다. 앞선 관찰에서는 상주 작업 집합이 약180 MiB였습니다. 고속 인덱스 교체 중에는 최대 약313 MiB, 대량 폴더 변경과 개발 빌드가 겹친 이전 테스트에서는 최대 약328 MiB를 사용했습니다. 고속 인덱싱 보조 프로그램도 작업 중에 별도 메모리를 사용하고 완료 후 종료합니다. [검증 기록](qa/QA_REPORT.md)에 측정 조건이 있습니다.

## 추가 검색 속도 개선

같은 C: 스냅샷 2,816,242개 항목으로 비교했습니다. 9회 반복 중앙값이며 검색 엔진 처리 시간입니다. 키 입력부터 화면 표시까지의 시간은 별도입니다. [수정 전](qa/speed-before.json)과 [수정 후](qa/speed-after.json)에 원본 측정값이 있습니다.

| 검색 | 이전 | 개선 후 |
|---|---:|---:|
| 이름 `report` | 40.04 ms | 20.03 ms |
| 이름 `보고서` | 29.48 ms | 11.60 ms |
| 이름 `*.pdf` | 43.76 ms | 20.91 ms |
| 전체 경로 `\windows\system32\` | 179.59 ms | 78.88 ms |

병렬 검색 작업마다 정규식 실행 상태를 나누고, 전체 경로를 검색할 때 경로 문자열·부모 경로 구성 버퍼를 재사용합니다. 입력을 이어 붙여 검색 범위를 좁힐 때에는 이전 후보가 65,536개 이하인 경우에만 재검사합니다. 후보 배열은 최대256 KiB이며 이전 인덱스를 메모리에 붙잡지 않습니다. 검색어 삭제·옵션 변경·인덱스 교체 시에는 필요한 전체 검색을 수행합니다. 접미사 와일드카드나 정규식 확장처럼 범위가 넓어질 수 있는 변경은 후보를 재사용하지 않습니다.

`보 → 보고 → 보고서` 연속 입력에서 마지막 단계는 전체 검색 약12.15 ms 대신 후보13개를 검사해 약0.029 ms였습니다. 전체 결과와 순서를 대조했습니다. 엔진 벤치마크 프로세스 작업 집합은 수정 전147.22 MiB, 수정 후149.47 MiB였고, 인덱스 할당량은126.12 MiB로 같았습니다. GUI 프로세스의 새 상주 메모리 측정값을 의미하지 않습니다.

처음 전체 정렬에는 여전히 약0.45~0.76초가 들며, 같은 기준의 반복 정렬은 약3 ms입니다. 다음 개선 후보는 인덱스 변경 때 정렬 순서를 더 많이 재사용하는 것과, 고속 갱신의 전체 스냅샷 읽기·재작성 비용을 줄이는 것입니다. 이 두 항목은 이번에 변경하지 않았습니다.

## 저장 위치와 개발

파일을 드래그할 때 시작 동기화나 백그라운드 변경 반영이 끝날 때까지 기다릴 필요는 없습니다. 현재 표시된 결과의 선택 파일을 전달하고, 드래그가 끝난 뒤 새 목록을 적용합니다. 실제 파일 작업·이름 변경이 진행 중이거나 새 검색 결과를 표시하는 동안에는 중복 작업을 막습니다.

검색 결과가 많아도 Windows 접근성 도구가 전체 행을 한꺼번에 펼치지 않도록, 접근성 트리에는 현재 화면의 행을 제공합니다. 화면 밖의 결과는 이름으로 찾아 이동할 수 있으며, 키보드·스크롤·다중 선택과 원래 검색 결과 수는 유지됩니다. 접근성 도구의 조회 때문에 검색창이 장시간 응답하지 않는 문제를 수정했습니다. 자세한 재현과 검사 범위는 `qa/QA_REPORT.md`에 기록합니다.

설정과 인덱스는 이전 버전과 호환되도록 `%LOCALAPPDATA%\QuickFind\`에 계속 저장합니다. `settings.json`은 마지막 설정, `index.bin`은 검색 인덱스입니다. 고속 모드의 `index.ntfs.bin`은 변경 동기화용 스냅샷이며, 옆의 상태·오류 파일은 보조 프로그램의 실행 결과입니다. 검색·인덱싱·경로 복사는 원본 파일을 수정하지 않습니다. 파일 메뉴에서 직접 선택한 이름 변경·삭제 등은 실제 파일 작업을 실행합니다.

개발에는 Rust MSVC 툴체인과 Visual Studio C++ Build Tools가 필요합니다. 이 작업 폴더의 Rust는 `.tools/` 아래에 설치되어 있으며 전역 PATH를 변경하지 않았습니다.

```powershell
.\build.ps1 build
.\build.ps1 run
.\build.ps1 test
.\build.ps1 bench -Root 'C:\'
```

스캔을 반복하지 않고 같은 스냅샷으로 검색 성능을 비교하려면 다음과 같이 실행합니다.

```powershell
.\dist\qf-bench.exe --root C:\ --from-cache qa\private-benchmark\index.qfi --out qa\benchmark-v2.json
```

독립적인 테스트 범위와 설정 저장 위치를 지정할 수도 있습니다.

```powershell
.\dist\Hyperfinder.exe --root 'C:\some-folder' --data-dir 'C:\some-test-data'
```

`qa/private-*`에는 실제 파일명이 포함된 로컬 인덱스와 테스트 설정이 있으므로 버전 관리에서 제외합니다.

# 검증 기록

2026-10-15, 사용자 Windows PC에서 확인했습니다.

## 빌드와 기능 테스트

- Rust MSVC release 빌드 성공.
- 자동 테스트 17개 통과, 실패 0개.
- 한글 및 공백 파일명, `*`와 Unicode `?`, 리터럴 중괄호, 정규식과 오류 처리를 검증.
- 이름·경로·크기·생성일·수정일 정렬 및 캐시 정렬 순서 일치를 검증.
- 누락된 메타데이터는 양방향 정렬에서 마지막에 표시.
- 스캔 취소, 중복 검색 범위, 정션 순환 방지 검증.
- 파일·폴더 생성, 수정, 이름 변경, 삭제의 증분 인덱스 갱신 검증.
- 저장 인덱스 교체·복원, 잘린 파일·잘못된 길이 거부 검증.
- Windows 전역 단축키의 실제 등록, 변경, 충돌 처리, 해제 검증. 키 입력은 주입하지 않음.

## 실제 화면 확인

- 테스트 폴더 8개 항목이 다크테마와 한글 글꼴로 표시됨.
- `*.xlsx` 검색 결과에 해당 파일 두 개가 표시됨.
- 결과 행 한 번 클릭 후 한글과 공백을 포함한 전체 경로가 클립보드와 정확하게 일치함.
- 사용자 물리 Esc 입력으로 Computer Use가 중지됨. 이후 화면 자동조작은 하지 않음.
- 마지막 개선본의 단축키 호출·숨김·재호출, 설정 저장, 키보드 탐색에 대한 전체 화면 검증은 완료하지 못함. 해당 코드는 빌드와 단축키 백엔드 테스트를 통과함.

## 실제 파일 성능

최초 C: 스캔과 이후 같은 스냅샷을 이용한 최종 엔진 측정입니다. GUI 렌더링 시간과 입력 전달 시간은 포함하지 않습니다. 검색 시간은 동일 검색 9회 중앙값이며, 파일 내용은 읽지 않았습니다.

| 항목 | 최종 결과 |
|---|---:|
| 파일·폴더 | 2,743,916개 |
| 폴더 경로 사전 | 426,279개 |
| 최초 전체 스캔 | 123.441초 |
| `report` | 17.07ms |
| `보고서` | 12.69ms |
| `*.pdf` | 12.79ms |
| `*test*` (104,651개 결과) | 18.30ms |
| 정규식 `\.(pdf\|xlsx\|docx)$` | 32.21ms |
| 반복 전체 정렬 | 약 24~38ms |
| 최초 경로 정렬 캐시 준비 | 약 963ms |
| 엔진 프로세스 작업 집합 | 558.1MiB |
| 벤치마크 최대 작업 집합 | 733.8MiB |
| 저장 인덱스 | 190,500,635바이트 |
| 저장 인덱스 재읽기 | 약 482ms |

메모리 값은 모든 정렬 열의 캐시를 준비하고 저장·복원 검증도 거친 벤치마크 프로세스 값입니다. GUI의 그래픽·글꼴 자원은 추가로 사용되며, 앱의 전체 C: 인덱스 메모리와 유휴 CPU는 이번 화면 검증에서 측정하지 않았습니다. 8개 항목 테스트 화면에서 측정한 유휴 CPU는 3.018초 동안 CPU 시간 15.62ms였고 작업 집합은 약 150MiB였습니다.

`qa/benchmark-initial.json`은 첫 구현 측정, `qa/benchmark.json`은 최종 검색 엔진 측정입니다. 초기 `*test*` 중앙값 약151ms와 메모리657MiB에서 개선했습니다.

## 구현 범위

- 현재 기본 인덱서는 일반 권한 Win32 폴더 열거 방식입니다.
- MFT/USN 기반 초기 인덱싱 및 종료 중 변경 이어 읽기는 구현하지 않았습니다.
- 읽기 전용 MFT 이름 열거 진단은 이 PC에서 Windows 오류5(접근 거부)로 불가했습니다. 관리자 실행이나 권한 설정 변경은 하지 않았습니다.
- 앱이 꺼져 있는 동안의 변경은 재실행 후 전체 스캔으로 확인합니다. 기존 인덱스는 먼저 검색할 수 있습니다.
- 폴더 총용량, 파일 내용 검색, 서비스 설치, 시작 프로그램 등록은 포함하지 않았습니다.

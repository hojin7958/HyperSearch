# QuickFind 0.2 검증 기록

2026-10-15, 사용자 Windows PC에서 확인했습니다. 이전 버전 기록은 `QA_REPORT-v0.1.md`입니다.

## 빌드와 자동 검증

Rust MSVC release 빌드와 자동 테스트 **65개**를 통과했습니다. 별도로 명시 실행하는 NTFS 상태 파일 IO 벤치마크 1개도 통과했습니다. 목록 갱신 후 행 ID가 바뀌어도 올바른 파일을 선택하는지, 같은 파일명의 다른 폴더를 구분하는지, 검색/정렬 변경 시 이전 화면 복원을 취소하는지, 맨 위 위치와 임시 표시 캐시의 상한을 유지하는지도 검증했습니다.

검증 범위: 한글·공백·중괄호, 와일드카드·정규식, 다섯 열 정렬, 압축 레코드·문자열 공유, 이전 V1 캐시 변환과 손상 검사, 파일/폴더 생성·수정·이동·삭제, 접근 거부 항목 보존, 변경 없는 알림 건너뛰기, 전역 단축키 등록·변경·충돌·해제, NTFS 확장 레코드·논리 IOCTL·USN 부모 폴더 갱신, 캐시 저장/flush/종료 순서입니다.

동일 경로 10만 알림은 하나로 합쳐집니다. 서로 다른 경로 10만 알림은 4,096개 경로/2 MiB 상한을 넘겨 계속 쌓이지 않는 것을 확인했습니다. 변경 감지 콜백은 UI 채널을 기다리지 않습니다.

## 메모리와 응답 상태

egui 화면을 Win32 가상 목록으로 교체했습니다. 파일 레코드는 28바이트이며 파일명·폴더 구성 요소를 공유하고 정렬 캐시는 한 열만 유지합니다.

최종 배포 GUI는 자동 고속 동기화와 일반 변경 반영을 포함해 **133.7초/45회 관찰에서 응답 없음 0회**였습니다. 관찰 후반 작업 집합은 **169.81~170.02 MiB**, 마지막 private commit은 **139.70 MiB**였습니다. 시작 후 고속 인덱스 교체 중 최대 작업 집합은 312.90 MiB였고, 누적 CPU 시간은 24.47초였습니다. 원본 샘플은 `gui-runtime-v2.json`에 있습니다.

이전 수정본도 181.8초/61회에서 응답 없음 0회였고 상주 작업 집합은 약181 MiB였습니다. 개발 빌드의 대량 폴더 변경과 동시에 갱신하는 동안에는 최대327.95 MiB를 사용했습니다. 평상시 상주량과 일시적인 최대치를 구분해야 합니다.

고속 보조 프로그램은 작업 중 별도 메모리를 사용하고 완료 후 종료합니다. 작업 관리자에서 선택한 메모리 열에 따라 수치가 다를 수 있습니다.

## 응답 없음과 반복 새로고침

파일 변경 알림을 무제한으로 UI에 전달하고 끝없이 비우던 처리가 응답 없음과 메모리 증가의 주원인이었습니다. 실제 스레드 관찰에서 UI 스레드가 총364초 중356초의 CPU 시간을 사용했습니다. 알림을 경로별로 합치고 대기열·UI 처리량을 제한했습니다. 비활성 창에서는 최대15초 동안 변경을 모으고 다시 열 때 바로 반영합니다. 같은 메타데이터의 중복 알림은 정렬 캐시를 재사용합니다.

사용자가 확인한 목록 깜빡임은 변경 반영 때 결과를 0개로 비웠다가 다시 채우는 처리에서 발생했습니다. 마지막 수정은 보이는 행의 다섯 열·아이콘·경로를 최대256개/512 KiB 이내로 보관하여 기존 표시와 한 번 클릭 복사를 유지한 뒤, 새 결과를 한 번에 반영합니다. 비동기 처리 동안 목록 창을 숨기거나 다시 그리기를 꺼 두지 않습니다. 갱신 중 이전 행 ID로 파일을 열거나 삭제하지 않도록 제한하고, 선택과 스크롤 위치는 파일명/부모 경로로 다시 찾습니다. 우클릭 메뉴나 이름 변경 중에는 자동 갱신을 미룹니다. 전체 인덱스 복제는 사용하지 않았습니다.

## 화면과 셸 기능

파란 돋보기 ICO를 EXE에 포함했습니다. 실제 EXE에서 추출한 아이콘은 `app-icon-extracted.png`입니다. 창·작업표시줄·트레이는 같은 아이콘을 사용하며 알려진 확장자는 Windows 시스템 이미지 목록의 아이콘을 표시합니다.

결과 우클릭은 탐색기 클래식 `IContextMenu`이며 이름 변경은 호스트 목록 편집으로 연결합니다. 트레이는 열기/종료와 Explorer 재시작 시 재등록을 지원합니다. 닫기 후 재실행은 기존 창을 비동기로 복원합니다. 기본 수정일 역순과 마지막 검색어·정렬·열 너비·필터·단축키·글꼴·창 위치/크기·고속 동기화를 저장합니다.

초기 화면 검증에서는 다크테마·한글·확장자 아이콘·검색 결과와 한 번 클릭 경로 복사를 확인했습니다. 이후 사용자의 물리 Esc 입력으로 Computer Use가 중단되어 추가 화면 자동조작을 하지 않았습니다. **최종 배포본의 깜빡임 해소는 사용자가 직접 확인했습니다.** 최종 메뉴 클릭, 단축키 호출, 선택/스크롤 보존의 전체 화면 검증은 완료하지 못했습니다. 해당 기능의 코드 검토·자동 테스트와 실제 화면 검증을 구분합니다.

`dist/QuickFind.exe`와 `dist/qf-indexer.exe`를 최종 release 산출물과 SHA256으로 대조했습니다. 기존 사용자 설정과 인덱스는 `%LOCALAPPDATA%\QuickFind\backup-before-v02\`에 백업했습니다. 단축키 Ctrl+Alt+1, 글꼴12, 수정일 역순 및 창 위치를 유지하고 검증된 고속 캐시로 교체했습니다.

## 트레이 복원 수정

후속 실행에서 닫기 버튼으로 숨긴 뒤 재실행하면 응답 없음으로 보이는 현상을 실제 UI에서 재현했습니다. 숨긴 동안 UI 스레드의 높은 CPU 사용량을 확인했습니다. 숨긴 창과 작업/복원 알림까지 대화상자 탐색 처리에 넘기던 경로를 제한했습니다. 이제 해당 처리는 보이고 활성화된 창에 속한 키보드 메시지에만 적용합니다. 숨길 때 키보드 포커스도 해제합니다.

트레이 클릭·전역 단축키·다시 열기·명령 처리를 트레이 창 프로시저로 옮겼습니다. 바깥 메시지 루프를 통하지 않는 직접 메시지나 메뉴 내부 루프에서도 처리됩니다. 숨긴 테스트 창으로 복원/작업/셸/변경 메시지를 게시해 실제로 전달되는지, 직접 및 게시된 트레이 이벤트가 도착하는지, 종료 후 단축키가 해제되는지를 자동 테스트로 검증했습니다. 테스트는 키보드/마우스 입력을 주입하지 않습니다.

후속 UI 재현 중 사용자가 물리 Esc로 Computer Use를 중단하여 이후 화면 자동조작은 하지 않았습니다. 수정본을 다시 빌드해 배포·실행한 뒤, 사용자가 트레이로 숨긴 창이 바로 다시 열리는 것을 직접 확인했습니다. 사용자가 변경한 글자 크기10, 검색어, 창 위치와 Ctrl+Alt+1을 유지했습니다.

## 경로 열기와 Delete 키

우클릭 메뉴 맨 위에 `경로 열기 (파일 탐색기)`를 추가했습니다. 파일은 Shell PIDL API로 상위 폴더에서 선택하며, 폴더는 직접 엽니다. 우클릭 시점에 캡처한 경로를 백그라운드 STA 스레드에 전달하고, COM 및 PIDL을 정리합니다. 탐색기 메뉴의 명령 ID와 앱 명령 ID가 겹치지 않는 것을 코드 검토했습니다.

목록에 포커스를 두고 일반 `Delete`를 한 번 누르면 전체 경로가 있는 예/아니요 확인창을 표시합니다. 기본값은 아니요이며, 예를 선택해야 삭제 작업이 시작됩니다. 검색어와 이름 편집, 키 반복, Shift/Ctrl 조합 및 갱신 중인 행은 이 단축키로 삭제하지 않습니다. 확인창을 열기 전에 캡처한 경로를 유지합니다.

삭제는 별도 STA 스레드에서 Windows IFileOperation으로 수행합니다. 휴지통·되돌리기 옵션과 영구삭제 경고 옵션을 지정하고, 연결된 HTML 부속 폴더 등 선택하지 않은 연결 항목을 함께 처리하지 않습니다. PerformOperations 결과와 GetAnyOperationsAborted를 모두 검사하여 취소를 완료로 표시하지 않습니다. 완료·실패·취소 모두 대상 경로를 다시 확인하여 부분 삭제된 폴더도 목록에 반영합니다. 삭제 중 종료 요청은 파일 작업과 인덱스 반영 뒤에 처리하고, 반영 실패 시에는 쓰기 스레드 종료 후 파생 검색 캐시를 제거하여 다음 실행에서 오래된 항목을 불러오지 않도록 했습니다.

새 자동 테스트 3개는 전체 경로·루트·장치/특수 경로 검증과 성공/취소/실패 분류를 확인합니다. 이 테스트는 실제 파일을 삭제하지 않습니다. 이번 변경에서는 추가 화면 자동조작을 하지 않았으며, 메뉴 클릭·확인창·실제 휴지통 이동은 직접 화면으로 검증하지 않았습니다.

## 파일 단축키, 고속 새로고침, 열별 더블클릭

Ctrl+C와 Ctrl+X는 Shell 파일 데이터 객체를 클립보드에 넣습니다. CF_HDROP과 Preferred DropEffect, 유니코드 경로 텍스트를 제공하며, OleFlushClipboard로 앱 종료 후에도 붙여넣을 수 있도록 합니다. Ctrl+V는 선택 폴더(파일 행은 상위 폴더)에 Windows IFileOperation으로 복사 또는 이동합니다. 이름 충돌·권한·오류에 대한 Windows 확인 UI를 유지하고, 취소 여부도 검사합니다. 파일 경로만 보관하므로 파일 내용 전체를 메모리에 올리지 않습니다.

파일 클립보드가 있으면 다른 행을 클릭해도 이를 덮어쓰지 않습니다. Ctrl+Shift+C 또는 우클릭의 전체 경로 복사로 경로 문자열만 복사할 수 있습니다. 검색어·이름 편집에는 기존 텍스트 단축키가 적용됩니다. 붙여넣기 원본 목록은 최대4,096개/경로2MiB로 제한하고 클립보드 변경 시 다른 파일이 붙여넣어지지 않도록 중단합니다. 빈 클립보드나 잘못된 대상은 폴더 재검색을 하지 않습니다. 실제 붙여넣기를 시작한 경우 중단·실패도 양쪽 경로를 다시 확인합니다.

새로고침과 F5는 NTFS USN 변경분 갱신으로 통일했습니다. 전체 재색인과 Shift+F5는 보조 프로그램에 --rebuild를 전달하여 MFT부터 재수집합니다. 새 설정은 시작 시 고속 동기화가 기본이며, 기존 사용자가 저장한 자동 동기화 설정은 보존합니다. 파일 작업이나 증분 반영 중 새로고침을 누르면 완료 후 실행하여 관리자 승인을 취소했을 때 기존 목록을 잃지 않도록 했습니다. NTFS 변경 이력은 삭제·이름 변경·이전 수정일이 유지된 파일도 다루며, 수정일로만 범위를 자르지 않습니다.

이름 열 더블클릭은 해당 파일·폴더를 엽니다. 폴더 경로 열 더블클릭은 그 열에 표시된 상위 폴더를 별도 스레드에서 탐색기로 엽니다. 크기·날짜 열에는 더블클릭 열기 동작이 없습니다. Enter는 선택한 파일·폴더를 엽니다.

추가 자동 테스트3개는 실제 Shell 데이터 객체의 파일 목록·텍스트·복사/이동 효과, 한글·공백 경로의 임시 파일 실제 복사/이동 결과, 같은 폴더로의 이동 및 자기 하위로의 복사 거부를 확인했습니다. 전역 클립보드는 시험 중 변경하지 않았고, 임시 테스트 폴더만 정리했습니다. 키 입력·탐색기와의 붙여넣기·열별 더블클릭의 실제 화면 검증은 이번에 수행하지 않았습니다.
## 검색창 전체 선택과 검색 속도 추가 개선

검색 Edit 컨트롤을 서브클래싱하여 WM_SETFOCUS 및 WM_LBUTTONUP의 기본 처리 후 EM_SETSEL(0,-1)을 보냅니다. 기본 마우스 처리가 선택을 다시 취소하지 않도록 순서를 맞췄습니다. 포커스가 이미 있는 검색창을 다시 클릭해도 전체를 선택하며, 선택 변경 자체는 새 검색을 발생시키지 않습니다. 이번에 실제 화면 클릭 검증은 하지 않았습니다.

병렬 검색 작업마다 Regex 실행 상태를 복제해 짧은 파일명 검색에서 공유 실행 상태의 경쟁을 줄였습니다. 컴파일된 정규식 데이터는 공유합니다. 전체 경로 문자열과 폴더 트리 순회 버퍼는 작업 중 재사용하고 같은 부모 폴더가 이어지면 다시 구성하지 않습니다. 인덱스의 파일명·전체 경로 사본을 상주시켜 속도를 올리는 방식은 사용하지 않았습니다.

검색 세션은 같은 엔진·같은 검색 옵션에서 포함 검색어가 확장되는 경우 이전 결과를 후보로 사용합니다. 최대65,536개 u32 ID(256KiB)만 보관하며, 엔진은 Weak 참조로 보관해 변경 반영 중 이전 인덱스를 계속 살려두지 않습니다. 후보가 정렬되어 있고 정렬 기준·방향이 같으면 재정렬하지 않습니다. 검색어를 줄이거나, 옵션·인덱스가 바뀌거나, 접미사 와일드카드·정규식이 다른 결과를 포함할 수 있는 경우에는 전체를 검색합니다.

새 자동 테스트4개는 후보 재사용과 접미사/정규식 확장의 구분, 다섯 열·정렬 방향·옵션 및 엔진 교체 시 결과, 후보 수 제한과 약한 참조, 100,010개 항목의 병렬 전체 경로 검색이 기존 Unicode/정규식/와일드카드 결과·순서와 같은지를 검증했습니다. 총58개 테스트가 통과했습니다.

성능 비교는 새 전체 스캔 없이 같은2,816,242개 스냅샷으로 수행했습니다. speed-before.json / speed-after.json은 9회 반복 중앙값입니다. report 40.04→20.03ms, 보고서29.48→11.60ms, PDF43.76→20.91ms, Windows System32 전체 경로179.59→78.88ms였습니다. 일곱 검색의 결과 개수도 같았습니다. 연속 입력 보→보고→보고서에서 마지막 단계는 후보13개를 검사해0.029ms였고, 같은 새 엔진의 전체 검색12.15ms와 결과·순서를 대조했습니다. 키 입력부터 화면 표시까지의 지연은 측정하지 않았습니다.

인덱스 할당량126.12MiB는 같았으며 엔진 프로세스 작업 집합은147.22→149.47MiB였습니다. GUI 상주량이나 최댓값의 새 측정값은 아닙니다. 처음 전체 정렬은 여전히 약0.45~0.76초로 남아 있습니다. 당시 남았던 상태 파일 IO와 중복 저장 비용은 아래 후속 수정에서 측정·개선했습니다. 델타 저장 형식으로 바꾸지는 않았습니다.

## 멀티 선택, 설정 화면과 검색어 배경 강조

단일 선택 제한 LVS_SINGLESEL을 제거해 Windows 목록의 Ctrl 개별 선택, Shift 범위 선택, Shift+방향키를 사용합니다. Ctrl+A 전체 선택을 연결하고 선택 개수를 상태 영역에 표시합니다. 복사·잘라내기·경로 복사·Delete는 선택 집합을 캡처합니다. 확인창에는 선택 개수와 경로 최대8개 및 나머지 개수가 표시됩니다. 파일 작업 대상은 최대4,096개/경로 합계2MiB로 제한하고 초과 시 아무 항목도 처리하지 않습니다. 부모 폴더와 내부 항목의 중복 작업도 제거합니다. 붙여넣기 대상과 이름 변경 대상은 하나만 선택하게 합니다.

서로 다른 폴더의 파일은 desktop-relative Shell IDList Array와 CF_HDROP, CF_UNICODETEXT를 갖는 IDataObject로 처리합니다. 같은 폴더의 다중 우클릭은 Explorer의 다중 항목 메뉴를 사용합니다. 서로 다른 폴더의 다중 우클릭은 복사·잘라내기·삭제·경로 열기·경로 복사 메뉴를 제공합니다. IShellItemArray의 BHID_DataObject/BHID_SFUIObject는 평면 배열에 제약이 있어 교차 폴더 처리를 그 인터페이스에 의존하지 않습니다. [Microsoft 문서](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ishellitemarray-bindtohandler)를 확인했습니다.

갱신 중에는 선택 경로의 128비트 UI 식별값과 선택한 부모 경로만 임시 저장하며 기존 전체 인덱스를 붙잡지 않습니다. 결과가 바뀐 뒤 선택 집합·포커스·Shift 범위 선택 기준을 복원하고 사라진 항목은 제외합니다. UI 식별값은 파일 작업 대상 경로로 사용하지 않습니다. 실제 작업은 현재 결과에서 캡처한 경로로만 실행합니다.

홀짝 행 대비를 강화하고 선택 배경은 청색, 검색어 일치 부분은 노란 배경/짙은 글자로 그립니다. 보이는 이름·경로 셀만 처리하고 모든 결과의 강조 문자열을 상주시켜 두지 않습니다. 한글, 반복 일치, 대소문자, 정규식, 잘못된/빈 정규식, UTF-16 보조 문자와 이름·폴더 경로 경계를 넘는 일치를 검증했습니다. 생략 표시된 문자열 바깥은 강조하지 않습니다. 와일드카드는 별표 전체가 아니라 실제 입력한 문자열 부분을 강조합니다.

검색창은 글꼴 높이를 측정해 외곽 입력 영역 안에 세로로 가운데 배치하고 설정 버튼을 옆으로 옮겨 폭을 줄였습니다. 클릭 후 전체 선택은 유지합니다. 글꼴의 입력 검사와 재실행 로드 범위를 모두8~20pt로 바꿨습니다.

단축키 입력 칸은 포커스 중 기존 전역 단축키를 해제해 현재 단축키도 재입력할 수 있습니다. Ctrl/Alt/Shift/Win, 영문·숫자·기능키·숫자패드 조합을 문자열로 변환하고 저장 시 등록합니다. 포커스 이탈·취소·설정 종료 시 기존 저장 조합을 복원합니다. 키 변환의 등록값 왕복, 윗줄1/숫자패드1 구분, 실제 해제 후 재등록 및 충돌 보존을 자동 검증했습니다. 검색 폴더는 Windows IFileOpenDialog의 폴더 다중 선택 창으로 추가하고 목록에서 삭제합니다. 경로 비교로 중복을 막으며 저장 시 실제 폴더인지 확인합니다.

추가 검증은 전역 클립보드를 바꾸지 않고 임시 파일 두 개를 서로 다른 폴더에서 실제 복사·이동한 결과까지 확인했습니다. 사용자 파일을 삭제하지 않았습니다. 실제 마우스 Ctrl/Shift 클릭, 화면 색상·정렬, 단축키 캡처 및 폴더 선택 창 조작은 화면 자동화로 검증하지 않았습니다.

## 새로고침 IO 후속 개선

최종 배포본을 재실행한 뒤 보조 프로그램의 새 완료 기록에서10,197개 변경 기록,2,824,275개 항목, USN 재사용1개 볼륨 및 실행2.863초를 확인했습니다. 이는 관리자 확인을 기다리는 시간과 GUI의 전체 시작 시간을 포함하지 않습니다. GUI는3회 표본에서 모두 Responding=true, 작업 집합162.41~162.43MiB였고 검색어·옵션·정렬·열 너비·검색 범위·단축키·글꼴·시작 시 동기화 설정은 모두 유지됐습니다. [ui-update-runtime.json](ui-update-runtime.json)에 원본 확인값이 있습니다. 실제 마우스/키보드 화면 조작은 별도로 확인하지 않았습니다.

실행 단계 측정에서 전체 목록 생성이 약2.9초로 가장 큰 구간이었습니다. C:처럼 드라이브 전체 하나를 검색할 때 파일마다 전체 경로를 만들고 소문자로 바꾸는 범위 검사를 생략했습니다. 폴더 경로는 폴더마다 만들고 재사용하며 파일명도 임시 String으로 복사하지 않고 압축 저장소에 직접 전달합니다. 특정 폴더 범위나 여러 중첩 범위에는 기존 범위 검사를 유지합니다. 하드링크·정션·부분 범위·중첩 범위를 포함한 기존 검사에 전체 드라이브 경로와 일반 범위 경로의 이름/크기/생성일/수정일/폴더 여부 비교를 추가했습니다.

동일한 고정 스냅샷으로 각각3회 목록 생성 구간만 측정한 중앙값은2,919.97→1,739.81ms입니다. 생성 항목2,816,451개, 인덱스 할당132,257,802바이트는 전후 동일했습니다. 실제 GUI의 전체 새로고침 시간이나 전체 프로세스 메모리의 비교는 아닙니다. 해당 원본 측정값도 refresh-io.json에 포함했습니다.

고속 보조 프로그램이 이미 저장한 검색 캐시를 GUI가 Ready 이벤트에서 다시 저장하던 작업을 제거했습니다. NTFS 상태 파일은1MiB 버퍼를 사용하고 각48바이트 레코드를 한 번에 인코딩해 기록합니다. 포맷과 저널 체크포인트 처리 방식은 유지합니다. 보조 프로그램의 완료 JSON에 로드/볼륨 처리/예외 복원/목록 생성/상태 저장/캐시 저장 단계별 시간을 추가했습니다.

동일한196,086,655바이트,2,837,727개 노드의 상태 파일을 복사해 전후 각각3회 측정했습니다. 중앙값 기준 로드211.12→180.43ms, 저장400.45→155.67ms입니다. 파일 로드·저장 합계는 약611.57→336.10ms이며 **새로고침 전체 시간의 비교가 아닙니다**. 관리자 권한이나 원본 NTFS 볼륨 접근 없이 상태 파일 읽기·개별 임시 파일 쓰기만 측정했습니다. 원본 기록은 [refresh-io.json](refresh-io.json)입니다. 실제 새로고침은 변경 개수, 메타데이터 IOCTL, 전체 인덱스 재구성·정렬 비용도 포함합니다.

## 파일 드래그앤드롭 연결 (2026-10-16)

파일 목록에 LVN_BEGINDRAG 처리가 없어 외부 프로그램으로 드래그가 시작되지 않았습니다. 선택한 전체 경로를 캡처하고 UI STA에서 OleInitialize와 SHDoDragDrop을 사용하도록 연결했습니다. 기존 Shell IDList Array와 CF_HDROP 파일 데이터는 공유하되 드래그에는 Preferred DropEffect를 강제하지 않습니다.
